# 교환 대시보드 탭별 기능 가이드

> 이 문서는 사이드바에 있는 각 화면(탭)이 **무엇을 보여주고, 누가 왜 봐야 하는지, 데이터가 어디서 오는지**를 정리합니다.
> 실제 코드를 하나하나 열어서 확인한 내용만 담았습니다 — "이렇게 되어야 한다"가 아니라 "지금 실제로 이렇게 동작한다"를 기준으로 썼습니다.
> 작동 안 하는 부분/미완성 부분도 숨기지 않고 그대로 적었습니다 (하단 [⚠️ 미완성·주의 페이지](#️-미완성주의-페이지) 참고).

**데이터 원천은 두 곳**입니다.

1. **구글시트** (`api/_sheets.js`) — 교환 접수 데이터. `[자사몰] 교환`, `[외부몰] 교환`, `[불량] 교환`, `재고관리` 4개 워크시트를 읽어옵니다. 재고관리 시트의 재고수량은 헤더명이 없는 J열이라 REST API로 별도 조회해 붙입니다.
2. **BigQuery** (`api/_bigquery.js` · `api/shipments.js`, 2026-07-28 추가) — 판토스 WMS **출고량** 데이터(`verish-pm.cx.daily_channel_sku_stockout`). 교환 건수를 출고량으로 나눈 **교환율·불량률**을 계산하는 데 씁니다. `GET /api/shipments?start=&end=`로 조회하며, 하루 1회 갱신되는 데이터라 서버·CDN·프론트 3단 캐시를 둡니다.

> **교환율의 의미**: 예전에는 교환 "건수"만 봤기 때문에 "많이 팔려서 교환도 많은 것"과 "진짜 문제가 있는 것"을 구분할 수 없었습니다. 출고량을 분모로 두면 이 구분이 가능해집니다. 단, 소량 출고 상품은 1~2건만으로도 비율이 크게 튀므로 **최소 출고량 필터**(랭킹·히트맵에 적용)로 왜곡을 막습니다.

> **분모 범위**: 출고 데이터 중 `channel_status='국내-B2C'`만 씁니다(B2B·오프라인·해외·교환출고 제외). 자사몰 = `카페24(신)`, 외부몰 = 그 외 국내-B2C 채널.

> **네이버페이 주의**: 시트에서는 `[외부몰] 교환`에 기재되지만 실제로는 **자사몰 비회원 주문**이라 출고량이 `카페24(신)`에 포함됩니다. 그래서 교환율 계산 시 분자를 자사몰 쪽으로 옮깁니다(`src/lib/rate.ts`의 `JASA_SCOPED_OEBU_CHANNELS`). 개별 채널 교환율은 출고량을 분리할 수 없어 "자사몰 합산"으로 표시됩니다.

## 1. 종합 대시보드 📊
`src/pages/OverviewDashboard.tsx` · 사이드바 최상단 · **경영 보고용 첫 화면**

**목적**: 각 채널 페이지를 하나씩 안 봐도 10초 안에 "지금 상황이 어떤지 + 뭐가 급한지 + 부서별로 뭘 봐야 하는지"를 파악하는 화면. 딥다이브는 아래 2~4번 페이지가 담당하고, 여기는 요약·트리아지·경보 역할만 함.

**화면 구성** (위에서부터):
- **출고 매칭 상태 칩** (헤더 우측) — 교환 데이터와 출고 데이터가 몇 % 매칭됐는지. 미매칭 건은 클릭하면 상품명 목록을 볼 수 있음(사은품·세트 등 출고 테이블에 없는 품목이 대부분). 출고 조회가 실패하면 "교환율 지표 비활성" 배너로 바뀜.
- **품질 급증 경보** (조건부) — 특정 상품의 **불량률**이 직전기간의 2배 이상이고 출고 100개 이상·3건 이상이면 빨간 배너로 노출. 예전엔 "건수" 기준이었는데 물량 많은 상품이 계속 잡히는 문제가 있어 2026-07-28에 비율 기준으로 바꿨음. 출고 데이터가 없으면 건수 기준으로 폴백.
- **교환율 KPI 4종** (2026-07-28 신규): 전사 교환율 / 자사몰 교환율 / 외부몰 교환율 / **불량률**(제품결함÷출고). 각 카드에 "교환 N건 / 출고 M건"을 병기해 분자·분모를 바로 확인 가능.
- **건수 KPI 5종**: 전체 교환 접수, 자사몰/외부몰/불량 각 건수·비중, 미출고 합계
- **리스크 & 비용 지표 5종**: 출고 리드타임(중앙값), 출고 처리율, **회수 지연**(접수 7일+ 지났는데 반송장 미집화 — 재고 손실 리스크), **교환 배송비 수취 총액**, **반복교환 고객**(3회 이상)
- **추이 그래프**: 자사몰/외부몰/불량 일별 접수 추이 (그라데이션 영역 차트)
- **유형별 비교**: 도넛 차트
- **출고량 대비 교환율 추이** (2026-07-28 신규): 막대=출고량(좌축) + 선=교환율%(우축) 이중축. 출고 데이터가 없는 구간(2026-03 이전)은 선이 끊겨서 표시됨.
- **TOP 3 교환 발생 상품** — 건수와 함께 교환율 배지 병기, **미처리 요약(Aging)**, **부서별 현황**(생산/QC·물류·재무 한 줄 요약 + 해당 딥다이브 페이지 링크)

**누가 보면 좋은가**: 팀장/경영진 — 매일 처음 여는 화면. 물류·재무·생산팀도 하단 "부서별 현황" 카드만 봐도 자기 몫을 가져갈 수 있음.

**주의**: "회수 지연"은 자사몰+불량 시트 기준만 계산됨 (외부몰 시트에는 회수내역 열이 없음).

## 2. 자사몰 교환 분석 🏬
`src/pages/JasaMallExchange.tsx` · `[자사몰] 교환` 시트 기반

**목적**: 자사몰(Cafe24) 교환의 물량·정책·사이즈 패턴을 깊게 분석.

**화면 구성**:
- **자사몰 교환율**(히어로 카드, 2026-07-28부터 건수 대신 교환율이 대표 숫자) + 교환/출고 건수 병기 + 접수 전기 대비 증감률, 교환 처리 효율(도넛)
- **접수 추이 그래프** — 막대=출고량 + 영역=접수건수 + 선=교환율%(우축) 이중축
- **정책/비용 지표**: 무료교환 비중, 입금요청 비중, 선교환 비중(회수 전 먼저 출고한 건 — 물류 리스크), 교환 배송비 수취액 합계
- **사이즈 교환 방향 분석**: 사이즈업/다운/색상만변경/동일옵션 재출고 건수 (각 타일에 **"출고 1,000건당 N건"** 정규화 수치 병기) + **사이즈업률/다운률 TOP5 테이블** — 건수가 아니라 출고 대비 비율로 정렬하므로 물량 많은 상품에 쏠리지 않음. 최소 출고량 필터 적용.
- **상품별 옵션 교환 분석**: 상품 검색 → 어떤 옵션에서 어떤 옵션으로 이동했는지 Before/After 표시
- 전체 교환 랭킹 TOP 3

**누가 보면 좋은가**: CX팀(일상 운영), MD/기획팀(사이즈 가이드·그레이딩 개선 근거), 재무팀(배송비 정책 판단).

**누가 보면 좋은가**: 채널 운영 담당자, 물류팀(채널별 지연 원인 파악).

## 4. 불량 교환 분석 ⚠️
`src/pages/DefectiveAnalysis.tsx` · `[불량] 교환` 시트 기반

**목적**: "진짜 제품 결함"과 "운영 실수(전산오류 등)"·"비불량(변심 등)"을 분리해서 순수 품질 문제만 추적. 원래 불량 시트에는 변심·전산오류 건도 섞여 있어서, 그대로 집계하면 불량률이 부풀려짐.

**화면 구성**:
- **전사 불량률**(2026-07-28 신규, 제품결함÷전체 출고량) + 그룹 KPI 4종: **제품 결함** / **운영·물류 오류** / **비불량(변심 등)** / 확인필요(사유 미입력). 전체 접수 건수는 불량률 카드 설명에 병기.
- 월별 그룹 스택 추이 + **월별 불량률 라인**(우축, 출고 데이터가 있는 2026-03 이후만 표시)
- 사유별 상세 (8개 카테고리: 원단, 패드·접착, 봉제·부자재, 오염·이물질, 착용감, 기타 제품불량, 운영·물류 오류, 변심·착용후) — 각 카테고리 클릭하면 상위 5개 상품/옵션 드릴다운
- 제품결함 분포 — 상품 대분류(브라/팬티 등)별, 채널별
- **상품별 불량률 랭킹**(2026-07-28 신규, 기존 "제품결함 상위 상품 TOP 3" 카드를 대체): 상품명·대분류·결함건수·출고량·**불량률**·주요 사유를 표로. 불량률 정렬이 기본이고, 대분류 셀렉트 + **최소 출고량 필터**(기본 100+)로 소량 출고 상품의 비율 왜곡을 걸러냄. 필터로 숨겨진 상품 수도 함께 표시. 행을 클릭하면 상품별 상세 분석으로 이동.

**누가 보면 좋은가**: 생산/QC팀(제품 개선 우선순위), CX팀(품질 이슈 조기 파악).

## 5. 교환 미처리 관리 ⏳
`src/pages/StuckCases.tsx` · `[자사몰] 교환` 시트만 대상 · **실제 운영 도구** (읽기 전용 아님)

**목적**: 자사몰 일반교환 중 지연되고 있는 건을 찾아서, 셀을 직접 고치고 고객에게 알림톡을 보내는 화면. 대시보드에서 유일하게 "작업"이 일어나는 페이지 중 하나.

**노출 조건**: 옵션 누락 또는 미입금 상태면 3일 경과부터, 그 외에는 출고일이 완전히 비어있고 7일 이상 경과한 건만 "미처리"로 잡힘.

**화면 구성**:
- 경과일 버킷(3일/5일/7일/7일+) 카운트 카드
- 사유 필터(옵션 누락/미입금/장기 미회수/입고됨/입고안됨/알림톡 미발송)
- 검색(주문번호/상품명/수령자)
- **테이블에서 출고일·교환 후 옵션·지불방법 셀을 클릭해 직접 수정** → 저장 시 구글시트에 즉시 반영
- **알림톡 발송 버튼** — 건별/조건 전체 발송 가능. 발송 이력은 브라우저 localStorage에 저장 (다른 PC/브라우저에서는 안 보임)

**누가 보면 좋은가**: CX 담당자 — 매일 처리해야 하는 실무 화면.

**주의**: 알림톡 발송 이력이 서버가 아닌 로컬 브라우저에만 저장되므로, PC를 바꾸거나 캐시를 지우면 이력이 사라짐.

## 10. 판토스 반품 처리 🔁
`src/pages/PantosOps.tsx` · 실제 동작하는 자동화 도구 (판토스_입고리스트 전용) — 2026-07-15에 기존 `반품-교환 연동`(`/reconcile`)과 `반품 시트 관리`(`/returns-sheet-maintenance`) 두 페이지를 합쳐 개편

**목적**: 판토스_입고리스트 기준 세 가지 도구를 한 화면에서 처리.

1. **반품-교환 연동**: 반품입고시트(`판토스_입고리스트`)와 교환접수시트(`[자사몰]`/`[외부몰] 교환`)를 대조해서, 반품이 들어온 걸 확인하고 교환접수시트의 출고일·확인완료일을 자동으로 채워줌. 화면 상단 탭으로 자사몰/외부몰을 전환. 반품이 들어오기 전에 이미 출고된 "선교환" 건은 출고일은 안 건드리고 확인완료일만 채움.
   - **사용법**: **① 미리보기 실행** → 정상 처리 예정 건수/이슈 건수 확인 → **② 시트에 반영** 클릭. 이슈는 자동 반영 대상에서 빠지고 수동 확인 필요:
     - `주문없음` — 교환접수시트에 해당 주문번호가 없음
     - `상품불일치` — 같은 카테고리 내에서 반품 상품/옵션/수량이 교환접수와 안 맞음
     - **`카테고리혼재`(2026-07-10 추가, 2026-07-15 보강)** — 같은 주문번호로 반품입고시트에 구분값이 다른 행이 섞여 들어온 경우(예: 자사몰교환 신청 상품 5개 + 신청 안 한 상품 5개가 같이 반품됨). 신청 개수만 보면 맞아서 예전엔 조용히 "정상 처리"로 넘어갔던 케이스라 별도로 분리함. 신청 상품이 먼저 들어와 처리된 뒤 상관없는 반품이 **나중에** 같은 주문번호로 들어오는 "지연 도착" 케이스도 2026-07-15부터 동일하게 잡아냄(완료 처리된 행도 혼재 판단에 포함).
     - `지불방법혼재` / `알수없는지불방법` — 같은 주문의 지불방법이 여럿이거나 규칙에 없는 값
   - **열 참조 방식(2026-07-09)**: 반품입고시트 열이 실시간으로 바뀌는 사고를 겪은 뒤, 모든 열을 헤더 텍스트로 찾도록 전환(`api/_columns.js`). 헤더를 못 찾으면 화면에 에러가 뜬다.
2. **구분값(E열) 재계산** — 새 반품 건이 들어온 뒤 실행하면 자사몰교환/외부몰교환/불량교환/반품 구분을 다시 계산해 채움 (판토스_입고리스트 전용, 리터니즈는 별도 화면에서 자체 처리 — 아래 11번 참고). 예전엔 무거운 구글시트 수식이었던 걸 코드로 대체함 ([업데이트기록.md](../업데이트기록.md) 2026-07-06 참고).
3. **완료건 → 히스토리 이관** — 같은 주문번호 그룹의 완료일이 전부 채워진 건만 히스토리 탭으로 옮겨서 미처리함을 가볍게 유지. 부분완료 그룹은 안전하게 보류.

**누가 보면 좋은가**: CX 운영 담당자 — 반품 처리 시 매번 실행하는 도구.

## 11. 리터니즈 반품 업로드 📤

**목적**: 리터니즈에서 다운로드한 "주문 조회 결과" 엑셀(.xlsx)을 업로드하면 리터니즈 워크시트 양식(주문번호/성함/판매처/상품명옵션명/실수량 등)으로 자동 변환 후 시트에 반영.

**사용법**: 엑셀 파일 업로드 → `lib/returnizeTransform.ts`가 자동 변환:
- 검품 제품 상태가 "제품 없음"/"타사 제품"인 행은 자동 제외
- 옵션 형식이 "제품코드 | 색상 | 사이즈" 3파트 또는 "색상-사이즈" 형태가 아니면 **확인필요**로 분류 — 상품명/옵션명을 직접 입력해야 반영 가능
- **구글시트에 반영** 클릭 시 `api/upload-returnize.js`가 행 추가 + 리터니즈 시트만 대상으로 구분값 자동 재계산까지 처리

**추가 도구(같은 페이지 하단)**:
- **구분값(C열) 재계산**: 업로드 없이 리터니즈 시트 전체 구분값을 다시 계산(`api/recompute-returnize.js`). 판토스의 "구분값(E열) 재계산"과 동일한 로직, 리터니즈 시트 전용.
- **반품-교환 연동(2026-07-15 추가)**: 판토스와 동일한 반품-교환 연동을 리터니즈 시트 기준으로 실행. 자사몰/외부몰 탭 전환, 미리보기→시트반영 2단계. 완료일은 리터니즈 시트에, 출고일은 공통 교환접수시트에 기입. UI는 판토스와 공용 컴포넌트(`src/components/ReconcileSection.tsx`, `source` prop만 다름), 백엔드는 `api/reconcile.js`의 `source` 파라미터로 분기.
